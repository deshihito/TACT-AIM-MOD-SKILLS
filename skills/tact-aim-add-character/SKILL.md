# TACT-AIM 系 MOD へ新キャラを追加する

対象: `TACT-AIM-MYTHOLOGY`（本命）と `TACT-AIM-MOD`。蒸留版には入れない。
ステータス・解放条件・二つ名などの仕様は作者が決める。未指定は仮置きとして報告で明示する。
全体の流れと検証ゲートは親スキル `tact-aim-add-content` に従う。

## 調査で先に確定させるもの

- `Character_2` / `Character_tree` のレコード形式
- `G.Character`（0始まりレコードオフセット）の使われ方
- ダメージ決済の位置（特殊能力のフック先）

## データ

置き場所は `src/generated/lists/stage/`。

1. `Character_2.ts` に 15 フィールド追加:
   [名前, スキル名, 攻撃, HP, 速度, 音量倍率, 索敵範囲, 再生（負数）, `""`×7]
2. `Character_tree.ts` に 10 フィールド追加:
   [名前, x, y, 解放種別, 解放量, 進捗, **リンク**, `""`×3]
   - リンク = **親レコードの0始まりオフセット**。レコード番号そのままではない
     （例: 親が13番目のレコードなら指定値は 120 ではなく 110 のような値になる）。
     **既存レコードのリンク値と親子関係を2〜3組実測してから決める。**
   - リンクに `"m"+月` を入れると季節限定扱いで線が描かれない。
   - 座標 (x, y) はツリー画面のノード配置そのもの。親ノードの近くで既存ノードと
     重ならない空き場所を選ぶ（既存の間隔はおおよそ100〜120刻み）。
   - 解放種別はゲーム側が評価できる既存の文字列（"Block damage" など）を再利用する。
     新しい種別は評価側の実装が別途必要で、作者の判断事項。
3. スキル名は既存スキルを指すこと。スーパースキルはスキル番号（Skill_2 の並び順）で
   SUPER_EFFECTS と対応するので、既存スキルの再利用なら自動で同じスーパーが付く。
   新スキルを作る場合は Skill_2 追加＋SUPER_EFFECTS 同位置追加＋スキル自体の実装が
   必要で、これも作者の判断事項（勝手に決めない）。

## 起動時上書きの罠

- Pen_All の初期化が作者専用枠（Crystal Gobo / Gem Cat）を tree の決め打ち位置
  （item 231/241）へ書く。新キャラがその位置に来る場合は書込先インデックスを
  後ろへずらす。**レコード追加のたびに衝突を確認する**
  （実績: 24番目のキャラ追加で 241/251 へずらした）。

## 特殊能力のフック

- 常時発動系（防御○○%など）はダメージ決済（`Bullet_damage`/`Bomb_damage` へ
  Buff_effect[3]/[4] を掛ける箇所）の直前で `G.Character_name` を見て
  係数を差し替えるのが既存の流儀。
- エンジンの床仕様を確認する: **弾ダメージは最低1に切り上げ、爆発は床なし**
  （係数0で完全0）。「100%軽減」でも弾は1ずつ通ることを報告に書く
  （実績: Metal Gobo は耐爆・防御100%でも弾は最低1ダメが残る）。

## コスチューム

- body / body+ / hand / banner の4種＋神話 ++（下記）。
  詳細な作り方は `tact-aim-svg-costumes`。
- 既存キャラの流用・変形は `tools/make_new_costumes.py` に処理を足す
  （再生成で Pen_All 登録行とマニフェストを差し替える作りになっている）。
  登録位置は Pen_All 内で流用元キャラの同種コスチュームの直後が既存の並び。
- **banner は必須**（無いとツリー画面でキャラ詳細が出ない）。

### バナー（キャラ詳細カード）

- ツリー画面でノードを選ぶと `Character_name + " banner"` のコスチュームが
  スタンプされる。名前が1文字でもずれると詳細カードが無言で出ない。
- 構造: 既存キャラの banner をコピーして作る。キャンバス 471×115、
  回転中心 (235.5, 57.5)。テキストは tspan が6個並ぶ:
  **[英語名, 日本語の二つ名, フレーバー文 ×4行]**。位置で対応するので
  順番を崩さず中身だけ差し替える。
- 帯の色はそのキャラのテーマ色（SVG 内の図形側）。流用元の色のままでも動くが、
  キャラの色に寄せるのが既存の並び。
- 二つ名とフレーバー文はユーザー向けコピー。起案はしてよいが仮置きとして報告で明示する。

## 神話スキン

- `tools/make_mythic_skins.py` の CHARS と CHAR_SPECS に追加する。
  個別の描き下ろしは CHAR_EXTRAS（Cat/Gobo が前例）。
- この生成スクリプトは開始時にマニフェストと ++ アセットを消してから作り直すので、
  途中で落ちるとマニフェストが消える。先に `make_new_costumes.py` を回して
  土台を復旧してから再実行する。
- 描き下ろしの流儀（顔の向き・色の扱い）は `tact-aim-svg-costumes` に従う:
  金色統一ではなく1体ずつ個別コンセプトで描くのが作者の方針。

## テスト

- `tests/pen-newcontent.test.mjs` の型で、レコード内容・ツリー連結・
  フックの発火を検証し、`package.json` の test チェーンへ組み込む。
- その後の検証ゲート（ダイジェスト再基準化・sb3 再生成・構造検証）は親スキルに従う。
