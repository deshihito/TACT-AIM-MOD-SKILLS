# TACT-AIM 系 MOD へ新アイテム（サブ）を追加する

対象: `TACT-AIM-MYTHOLOGY`（本命）と `TACT-AIM-MOD`。データの置き場所は武器と同じ
`Item_list` だが、サブには固有の経済と設置の仕組みがある。数値は作者が決めるもので、
未指定は仮置きとして報告で明示する。全体の流れと検証ゲートは親スキルに従う。

## サブの経済（Item_list のフィールド意味）

- 実効ストック = 容量（field2）× 倍率（field4）。使用で field2 ずつ減り、
  回復は FPS_temp/フレーム固定。
- つまり **field2 が「1回分のチャージ時間」そのもの**（小さいほど速く貯まる）。
  「N スタック」= field4、「貯まる速さ」= field2。
  例: クイックガードライトはクイックガードの4倍速 → 消費単位 120 → 30。
- 価格・スタック数・チャージ単位はこの換算で既存サブと比較してから置く。

## 設置型（地雷・C4 など）

- 振る舞い文字列は「設置」。プログラムは地雷が型:
  Mine stamp で味方にだけ半透明表示、Length で制限時間（切れると自爆）、など。
- **起爆信号パターン（隠しアイテム方式）**: 「構えている間だけボタンになる」アイテムは、
  1. Weapon_motion フックで Menu[75] を張り付けて通常のサブ連射を止める
  2. スロット名を隠しアイテム名へ一時差し替えして `Shot__c(Inventory, true)` を
     強制発射する（残弾は保存・復元して消費させない）
  3. Shot_create 先頭で隠しアイテム名を検知して本来の処理（レコードのフラグ立て等）を行う
  信号はクラウド経由で全クライアントに届く。
- 隠しアイテムにも Item_list レコードと English エントリが要る（件数一致）。
  カードやコスチュームを付けなければ店に並ばない。
- **隠しアイテムの idx10 は必ずそのアイテム名自身にすること。** 復号は idx10 を
  武器名として Player_shot へ渡すため、idx10 が本体名だと信号が本体の設置に化け、
  復号経路は残弾を消費しないので無限設置になる（C4 起爆の実績事故）。
  テストは復号が渡す名前で Shot_create を駆動して回帰を防ぐ。

## ガード系サブ（1マスガード等）

- 設置は Shot_create の「1マスガード」分岐が `C<武器名>` レコードを作る。
  Bullet_list に `C<武器名>` プログラムが要る:
  `["C<名>", "Guard", 耐久, "6", 摩耗率, 破壊時の生成物, "7", "-", 1.5, 0]`
- 耐久 = 被弾蓄積の上限。一番弱い弾でも蓄積 ≈ 1.7 × 攻撃補正なので、
  「一回で壊れる」は耐久 1。摩耗率は未被弾時の寿命を決める
  （耐久 ÷ 摩耗 ÷ FPS_temp フレーム）。
- **円形ガード**: Shot_create に新 behavior を足し、フラットな const 配列
  （[dx, dy, 角度] × N、SUPER_EFFECTS 方式）で各マスへ C レコード＋Create_guard を呼ぶ。
  Temp1 = 外向き角度にすると Guard の向きは +180 で格納され、
  外からの弾だけ受ける（内側からは撃ち抜ける）。
- **止めないフィールド（スライム等）**: Guard リストへ登録しなければ弾は止まらない。
  効果は Step 手順のフックで「弾の今いるマスに該当レコードがあるか」を走査して
  速度を変える。寿命だけなら `[Length, 8, 上限, "-"×6]` のみのプログラムでよい。
  設置物の見た目は `:名前` コスチューム（Draw_bullet が全レコードを ":" + 名前で描く）。

## 特殊武器モード（搭乗系）の入り方

- 現在の Inventory_2（31フィールド）を Temp_inventory へ退避 →
  `G.Special_weapon = "1"` → Inventory_2 を 5枠×6フィールド＋末尾 "1" で再構築 →
  Set_inventory で各枠を埋める。
- **枠数は枠1のタイプ字段（item 2）を Special_weapon_2 で引いて決まる**ので、
  枠1のタイプは必ず Special_weapon_2 に載っている名前にすること
  （サブタイプでは解決できない）。
- 発射可否（Full）は Item_list ではなく **枠の字段3（残弾）/4（容量）が正** かで決まる。
- 終了時は Temp_inventory から31フィールド復元＋Special_weapon = "0"。
  Respawn の復元と競合しないよう、モード専用フラグと Special_weapon == "1" の
  両方を条件にする。

## 既存武器の弱体/派生版（ライト版）の作り方

- 特殊武器の op（例 "About shield cannon"）はダメージ等が**ハードコード**で
  引数を取らない。派生版は Bullet_action 内に新 op 分岐を写して数値だけ変える
  （実績: "About shield cannon light" = Damage 50→17、爆発 10/8/5→3/3/2、炎は青）。
- 派生アイテムの behavior 文字列は本家と同じにすると Shot_create のマズル・煙などの
  特殊処理を流用できる。レコード名 = アイテム名になるため、引くプログラムは
  派生側のものになる（Bullet_list に派生名のプログラムを置く）。
- 時間制限つきの自己強化（装甲など）はクラスフィールドのタイマーで持つ:
  Shot_create の先頭で「武器名一致 かつ 発射者が自分（P.item(1) == G.ID）」のときに
  タイマーをセットし、効果は All の速度計算（本家のシールド回復の直後）へフックして
  毎フレーム減算する。**他人の発射で自分のタイマーが立たないよう ID チェック必須**
  （テストでも検証する）。

## ワープ系アイテムの注意

- 弾レコードのプログラムから所有者本人を動かすことはできない（Set position は逆向き）。
  ワープ等は Weapon_motion 先頭のフックで「自分のレコードが壁セル
  （round(x/50)/round(y/50) ∈ Bullet_wall）」を検知して処理する。
  直前位置はプログラム側で CS val の `"[3"` / `"[4"` 参照を使って
  レコードの空きフィールドへ毎フレーム控える。
- 銃口位置（マズル50先）は壁セル内になり得る。生成直後に発生セルが Bullet_wall に
  含まれる間は発射者側へ引き戻す調整を入れる（ワープ先が壁の中になるグリッチ防止）。
  フック側でもワープ先が壁内なら現在位置側へ引き戻し、最後まで壁内なら移動しない。

## コスチュームとショップ

- held / @アイコン / *ショップカード。* は「* コスチュームの連続ブロック」の
  内側に置くこと（詳細は tact-aim-add-weapon と tact-aim-svg-costumes）。
- 設置物には `:名前`、ガードには `C<名前>` 系のコスチュームが要る。

## テスト

- データ整合（件数・フィールド値）、設置・起爆・ガードの一回破壊 vs 通常版の生存、
  タイマーの発火条件（自分の発射でのみ立つ）を検証する。
- その後の検証ゲートは親スキル `tact-aim-add-content` に従う。
