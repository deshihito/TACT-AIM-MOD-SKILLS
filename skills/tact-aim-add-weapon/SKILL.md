# TACT-AIM 系 MOD へ新武器を追加する

対象: `TACT-AIM-MYTHOLOGY`（本命）と `TACT-AIM-MOD`。蒸留版（原作の純粋コピー）には入れない。
仕様の数値（ダメージ、価格、連射間隔など）は作者が決める。未指定は仮置きとして実装し、
報告で「仮置き」と明示する。全体の流れと検証ゲートは親スキル `tact-aim-add-content` に従う。

## 調査で先に確定させるもの

- `Item_list` のレコード形式、弾プログラム（Bullet_list）の文法
- 発射経路（Weapon_motion → Shot__c）、近接の Sword damage ハンドラ
- 流用元にする既存武器（同種別・同挙動のもの）を1つ決め、その全データを実測する

## データ

1. `Item_list.ts` に 14 フィールド追加:
   [名前, 種別, idx2（重量系）, 価格, idx4, idx5（idx6=1 のときズーム）,
   スコープ旗 idx6, idx7, idx8, サウンド id idx9, コスチューム名 idx10,
   **挙動文字列 idx11**, 弾名 idx12, `""`]
   - 価格欄の `"mMM"` は季節限定表記。
   - **idx10（コスチューム名）は重要**: 発射の復号（Load cloud data → Player_shot）は
     武器名として idx10 を渡す。Shot_create で武器名に依存する処理を持つ武器は、
     idx10 を必ずアイテム名自身にすること（ズレると信号が通常発射に化ける事故が起きる）。
   - スコープ対応武器は idx6 = `"1"` がフラグ、idx5 がスコープ係数
     （例: 銛スナイパーは idx5=3, idx6=1）。スコープ中はカメラがマウス×係数へ寄る。
2. `English_weapon_name.ts` に英語名を1件追加（件数が Item_list と一致すること）。
3. `Bullet_list.ts` に弾プログラムを追加（`""` 終端の可変長レコード）。
   - 近接は `["名前", "Sword damage", ダメージ係数, 射程, 弧度, ノックバック,
     "Length", 6, 14, "-"×6, ""]` が大剣の型。ダメージ係数は発射者の
     攻撃倍率（クラウド field 24）と掛け算される。
   - **命令アリティを厳守する**（実測の早見は親スキル末尾）。特に Length は
     [フィールド, 上限, 生成物×6] の **8 引数**。`[Length, 7, 60, "Damage", ...]` と
     書くと Damage 命令が生成物に食われ、寿命切れで `"Damage"` という名のレコードに
     化けて、プログラムを引けず先頭（ピストル）のプログラムで動く
     「ダメージ25の見えない幽霊弾」になる。寿命で素消えさせたい場合は
     生成物に `"-"`×6 を明示する。ピストルのプログラムが正形の見本。
     新規プログラムはアリティ表でパース検証してから入れる。
4. Pen_All.ts の `Bullet_name` SList の末尾に弾名を追加。

## 名前の完全一致（最重要）

- **武器名と弾プログラム名は完全一致が必須。** Shot_create は武器名でレコードを作り、
  Bullet_action はレコード名でプログラムを引く。名前がずれると弾が無言で機能しない
  （実績: 武器 "Chase gun" に対してプログラム名を日本語にした事故）。
- 英語名の武器は、プログラム名・Bullet_name・`:弾名` コスチュームも英語名で統一する。
- 弾には必ず **`:弾名` コスチューム**が要る。Draw_bullet は `":" + レコード名` を
  描くので、無いと切替が失敗して弾が完全に見えない（エラーも出ない）。

## 反動で飛ぶ武器

- 挙動文字列に `近接反動NN` を入れる。推進力 = 50 − NN（大剣 = 近接反動20 → 30）。
  比率指定（例: 大剣の1.5倍 = 45）は NN = 05。反動は発射ごとの照準方向へ掛かる。

## 連射・連鎖などの特殊挙動

- `Weapon_motion`（毎フレーム実行）に tick を置き、`Shot__c(G.Inventory, true)` の
  ように Full へ真を渡すと強制発射できる（compare() の結果を直接渡す前例あり）。
- 発射は記録され、受信側は発射者の現在の照準でデコードするので、
  連鎖の向きは発射ごとにマウスで制御できる（実績: 抜刀剣の3連続飛行、12フレーム間隔）。
- 持ち替え検知は `G.Inventory_2.item(G.Inventory + 1)` と装備名の比較。
  連鎖は持ち替えで取消すのが既存の流儀。
- **detranspile は新規手順を作れない。** 新しい毎フレーム処理は既存手順の中へ
  ゲート付きで直接書く（親スキルの落とし穴参照）。

## 新しい弾の命令（op）を足す場合

- 既存 op の写しが基本（例: Homing の写しで目標をマウスワールド座標にした
  "Mouse homing"）。操舵のようなマウス依存処理は発射者の画面のみ
  （`T.item(1) == G.ID`）で効かせ、他画面では直進させる
  （マウス位置は同期されないのでマルチでは近似になる、と報告に書く）。

## 発射音

- 武器の発射音は Item_list の弾名（idx12）と同名のサウンド。同名サウンドが
  無いと無音になる。新規合成音は manifest に `"sound": true` で登録する
  （実績: 抜刀剣の抜刀音、22050Hz で合成）。

## コスチューム（詳細は tact-aim-svg-costumes）

- held（素の名前）/ @アイコン / *ショップカード の3種。
- **ショップの品揃えは `*` コスチュームの連続ブロックで決まる**: Set_val が *Gun から
  nextCostume で辿り、最初に「*」でない名前に当たると停止する。新武器の * は必ず
  ブロック内（既存の同系統カードの直後）に置く。TS 側の登録アンカーと
  manifest の `"after"` の両方をブロック内に指定する
  （after 無しだと sb3 では末尾へ落ちてブロック外＝店に並ばない）。
- * カードの中身は武器の絵ではなくテキストカード（カテゴリ表記・英語名・説明文）。
  説明文の性能記述はデータと必ず照合する。起案は仮置きとして報告で明示する。
- @ アイコンは流用元武器の @ と同一キャンバス・回転中心で描く。

## テスト

- `Weapon_name.itemNum(新武器)` = 期待位置、弾プログラムの値、反動比、
  連鎖フックの発火/取消を検証する（`tests/pen-newcontent.test.mjs` の型）。
- 件数を直書きしている既存テスト（pen-init の長さ期待値など）も新しい件数へ更新する。
- その後の検証ゲート（ダイジェスト再基準化・sb3 再生成・構造検証）は親スキルに従う。
