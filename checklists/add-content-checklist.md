# 追加時の確認項目チェックリスト

新武器・新アイテム・新キャラ・新概念を追加するとき、push 前に全部確認する。
詳細な理由と手順は各スキルの `SKILL.md` 側にある。これは一覧版。

## 着手前

- [ ] 対象レポは MOD 側か（蒸留版＝原作の純粋コピーには入れない）
- [ ] 関係するレコード形式・連結規則・フック位置を、既存データとコードで実測した
- [ ] 仕様の数値・デザインで未指定のものは「仮置き」として一覧化した（勝手に確定しない）
- [ ] 新しい解放種別・新スキル・完全新規の効果が必要なら、それは作者の判断事項として切り分けた

## データ

- [ ] 追加先リストのレコード形式（フィールド数・順番・終端 `""`）が既存と一致している
- [ ] 件数が位置で対応するリスト同士（例: Item_list と English_weapon_name、
      Buff 表と Buff_name）で一致している
- [ ] 武器名・弾プログラム名・Bullet_name・`:弾名` コスチューム名が完全一致している
- [ ] 弾プログラムの命令アリティを検証した（特に Length = 8 引数。生成物は `"-"`×6 を明示）
- [ ] ステージリストを編集した場合、buildSb3 の「ステージリスト上書きフック」の対象に入っている

## ロジック

- [ ] 新規手順（メソッド）を足していない（detranspile は新規手順を作れない。
      毎フレーム処理は既存手順の末尾へゲート付きで直接書く）
- [ ] detranspile が壊れる書き方をしていない（`B()` 入りの入れ子三項演算子、
      素のブロック文、`break`、ブロック本体なしの for、Math.min）
- [ ] 他人の発射で自分の状態が立たないよう、必要な箇所に発射者 ID チェックがある
- [ ] クラウド形式は固定長のまま（新しいクラウド変数は追加できない。上限は CLOUD1〜10）
- [ ] 効果の語彙は既存の Bullet_name / Buff_name の中だけを使っている
      （完全新規の効果は受信側の処理追加が別途必要）

## コスチューム / SVG

- [ ] 登録が2箇所ともある（Pen_All.ts のコスチューム表 と tools/mythology-costumes.json）
- [ ] キャラには banner がある（無いとツリー画面で詳細カードが無言で出ない）
- [ ] 武器の `*` ショップカードが「* コスチュームの連続ブロック」の内側にある
      （manifest の `"after"` もブロック内を指定）
- [ ] 弾には `:弾名` コスチュームがある（無いと弾が無言で見えない）
- [ ] バフには `^<バフ名>` アイコンがある
- [ ] キャンバス・回転中心が流用元と同一で、顔の向き（+x 向き、頭頂は −x 側）を確認した
- [ ] 色は原作パレットの実測色だけを使い、プレビューを body+ / body++ / ポートレートで目視した

## テストと sb3（検証ゲート）

- [ ] TS を編集したので、個別テストの前に `npx tsc` を回した
- [ ] `npm test` 全合格。件数を直書きしている既存テストの期待値を更新した
- [ ] Pen_All.ts を編集した場合、`npm run detranspile:check-distilled` の差分が
      意図した文の追加・変更だけになっている
- [ ] 起動ダイジェストの再基準化: 新旧の G 全項目を比較し、差分が
      「追加データ由来のリスト長と中身」だけであることを確認した
      （スカラーや描画カウンタに差が出たら実装ミスを疑う）
- [ ] `npm run detranspile:build-distilled` で sb3 を再生成した
- [ ] `python3 tools/validate_sb3.py out/*.sb3` が **0 issues**
- [ ] `bash tools/verify-distilled.sh` が **BOOT TEST: PASS**（往復等価）
- [ ] sb3 の中身を直接確認した: 新コスチュームの存在、マニフェスト全アセットの同梱、
      ステージリストの長さ、クラウド変数が CLOUD1〜10 のみ
- [ ] 成果物 sb3 を所定の場所へコピーし、`out/` を消した

## 報告

- [ ] 仮置きにした値・コピーを全部「仮置き」と明示した
- [ ] テスト件数・構造検証の件数・ダイジェストの差分内容を数字で書いた
- [ ] MOD 用ノート（MYTHOLOGY_NOTES.md 等）に結果を残した
- [ ] GitHub 書き込みは集約した（commit / push は各1回）
